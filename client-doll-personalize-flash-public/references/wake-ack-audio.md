# 本地“我在”录音导入

只在两步客户流程的第二步读取本文件：人格和回复风格已经由用户明确验收，用户随后提供用于“小酥肉”唤醒回应的本人或已授权录音。

## 用途边界

- 录音只用于设备本地播放“我在”，不上传、不用于云端声音克隆，也不代表用户批准任何 ASR、DeepSeek 或 TTS 调用。
- 先确认声音权利人和明确授权。内容应是自然说出的“我在”；若包含其他句子、第三人声音或无法判断，停止并让用户重新提供。
- 原始文件保持原处且不修改。若复制进客户工作区，只能放在该客户的 private_data；不跨客户复用，不进入 Git 或 Skill。
- 临时 WAV 在最终 PCM、哈希和构建完成后删除。应用镜像包含可提取的本人录音，只能保存在客户私有构建目录。

## 格式检查

1. 使用本机现有 ffprobe/ffmpeg 做本地只读检查，不为普通 M4A 另行下载解码器。
2. 接受能稳定解码的 M4A/AAC、WAV、MP3 等常见短音频；报告容器、编码、采样率、声道、时长和大小。
3. 拒绝无法解码、明显截断、纯静音、削波严重、超过 5 秒或含多段说话的输入。只报告信号统计，不转写或打印音频内容。
4. 原格式不能直接嵌入固件不是失败；运行时资产必须统一为 16000 Hz、单声道、16-bit signed little-endian PCM。

## 首尾各保留约 0.1 秒

- 用 ffmpeg silencedetect 或等价本地分析定位稳定语音区域。默认以 -45 dB、至少 30 ms 的安静区作为初始判定；环境噪声较高时可根据测得噪声底调整，但不得剪掉辅音起始或词尾。
- 忽略孤立的极短点击或编码毛刺，选择包含完整“我在”的单一稳定语音区间。
- 裁剪边界设为语音开始前 0.1 秒、语音结束后 0.1 秒；若原文件某侧不足 0.1 秒，补零到 0.1 秒。
- 转换后再次对最终 PCM 检测。首尾静音的接受范围是各 0.08 至 0.12 秒；超出则微调一次。最终时长不超过 2 秒，PCM 必须为偶数字节且不超过 64000 字节。
- 不做变声、变速、自动响度标准化或降噪；除首尾静音和必要的采样率/声道/位深转换外保留原声。若音量或噪声不合适，优先让用户重录。

## 集成和验证

1. 用母版现有 desktop_tool/ai_doll_tool/wake_ack_audio.py 验证临时 PCM WAV，并原子替换客户副本中的 firmware/components/doll_platform/assets/wake_ack_wozai.pcm。
2. 确认 PCM 和客户私有构建目录被 Git 忽略；记录源文件 SHA-256、最终 PCM SHA-256、字节数、时长、前后静音和“未联网/未上传”。
3. 运行 tests/test_firmware_wake_ack.py、TTS 音量回归测试和完整 ESP-IDF 构建。
4. 构建日志必须显示 Local wake acknowledgement embedded，ELF 必须包含 wake_ack PCM 的 start/end 符号；模型报告仍只包含 wn9_xiaosurou_tts2。
5. 当前交互顺序必须保持：检测“小酥肉” → 本地播放“我在” → 等待播放通道稳定 → 清空麦克风 DMA → ESP-SR VAD 录音 → 后续云链路。
6. 录音变化只要求重建和更新应用分区。已有客户板默认保留 NVS、两个 LittleFS 和 model；新板按 firmware-and-flash.md 的完整性分类处理。

## 真机边界

烧录前重新枚举串口并读取芯片、MAC、Flash 和 PSRAM。用户提供录音只批准本地处理和构建，不自动批准擦除、烧录或一次真实云端对话。若用户在同一条消息中已经明确指定目标板以及“新板完整烧录”或“已有板仅更新应用”，可在身份核对一致后执行该范围；身份或范围不明确时先展示结果并等待确认。
