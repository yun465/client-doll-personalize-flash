# 固件构建与烧录

本文件描述仓库内 ESP32-S3 N16R8 参考配置的具体实现。只有目标项目通过 [project-adaptation.md](project-adaptation.md)的兼容性检查后才使用下面的版本、模型和偏移；其他项目必须从自己的构建配置、分区表和生成的 Flash 参数解析实际值。

## 阶段边界

将动作拆成独立门禁：

1. 准备客户工作副本。
2. 本地人格分析与预览。
3. 人格写入工作副本。
4. 测试与离线构建。
5. 识别目标板。
6. 擦除或烧录。
7. 启动与本地功能验证。
8. 写入真实 Wi-Fi/API/音色配置。
9. 恰好一次真实云端对话。

“继续”只推进当前已说明的下一阶段，不自动批准擦除、烧录、真实秘密写入或付费调用。

## 构建前检查

- 当前目录必须是客户工作副本，不是其他客户目录。
- 读取 `AGENTS.md`、`PLAN.md`、`firmware/partitions.csv`、`sdkconfig.defaults` 和 Git 状态。
- 确认 `private_data/`、构建目录、录音、密钥、音色 URI、NVS 镜像和 Flash 备份均被忽略。
- 确认人格配置能通过现有公共配置校验，且没有秘密字段。
- 若本轮含本地“我在”录音，按 wake-ack-audio.md 记录授权、最终 PCM 时长、前后静音、大小和 SHA-256；确认原始录音、临时 WAV、PCM 和私有构建包均被 Git 忽略。
- 运行人格包、提示词、隐私过滤、设备人格和配网定向测试。

## 构建基线

- ESP-IDF：6.0.2。
- 芯片：ESP32-S3。
- Flash：16 MB。
- PSRAM：8 MB Octal，80 MHz。
- 唤醒模型：只打包 wn9_xiaosurou_tts2。
- 唤醒回应：本地播放客户授权的“我在”，等待播放稳定后清空麦克风 DMA。
- 录音端点：ESP-SR VAD 30 ms 帧、约 120 ms 连续语音确认起声、起声后 810 ms 静音自动停录、3 秒未起声取消、最长 5 秒；VAD 不可用时退回最长 5 秒。
- 使用参考配置时，分区表必须与 `current-project-baseline.md` 一致；其他项目以自己的受版本控制分区表为准。

使用当前机器已安装的 ESP-IDF 环境，构建目录放在客户工作副本外或 Git 忽略目录。不要复用另一个客户的旧构建目录。构建后记录：应用大小、分区余量、模型清单、各镜像 SHA-256 和测试计数。

## 目标板识别

烧录前只做只读探测：

- 枚举当前串口，避免沿用历史 COM 号。
- 用 esptool 读取芯片类型、MAC 和 Flash ID/大小。
- 从启动日志确认 PSRAM 类型与容量。
- 把探测结果展示给用户，并确认哪一块是目标客户板。

若存在多个可疑串口或探测结果不是 ESP32-S3 N16R8，停止并请求用户指认。

## 烧录前 Flash 完整性分类

完成目标板身份确认后，先只读检查，不能仅凭“以前刷过”“MAC 没变”或应用分区能够写入就选择应用单刷。偏移和文件名必须来自本次构建的 `flash_args`、`flasher_args.json` 和分区表，不把下列示例当作另一版分区表的硬编码命令。

对当前 16 MB 基线至少检查：

- Bootloader `0x0`：应是有效 ESP 镜像，开头通常为 `0xE9`，并能与本次构建产物核对。
- 分区表 `0x8000`：不能是全 `0xFF`；解析结果必须与项目分区表一致。
- OTA 数据 `0x19000`：不能在需要 OTA 启动时缺失。设备启动后该分区可能被 Bootloader 合法更新，因此不要要求它永远等于最初镜像哈希。
- 应用 `ota_0` `0x20000`：应是有效 ESP 镜像并可做读回哈希校验。
- `doll_a` `0x620000` 与 `doll_b` `0x7A0000`：检查 LittleFS 超级块或尝试只读挂载；不能仅以“分区非空”代替文件系统有效性。
- 模型 `0x930000`：应能识别本次构建的模型内容，并确认只包含 `wn9_xiaosurou_tts2`。

检查 NVS 时只报告诸如 `wifi_secret_present`、`deepseek_api_key_present`、`siliconflow_api_key_present`、`custom_tts_voice_present` 的布尔值。不得读出、打印或保存实际 Wi-Fi 密码、API Key 或音色 URI。

把结果归入三类：

1. **完整已有板**：所有必需基础分区有效。按最小写入原则更新应用、人格或模型。
2. **空白或不完整板**：一个或多个必需基础分区为空、全 `0xFF` 或无效。先列出缺失分区、精确偏移、拟写文件及会保留的 NVS，再取得与实际写入范围相符的授权。
3. **状态冲突或无法确认**：分区表与构建不一致、两个 LittleFS 内容冲突、身份不符或读回失败。停止，不猜测、不覆盖。

只有读回分类完成后才能决定写入策略。若最初批准只是“应用单刷”，检查却发现基础分区缺失，必须说明新增写入范围并取得用户确认；不能把应用单刷授权自动扩大为基础分区恢复。

## 写入策略

### 新客户板

只有用户明确说明“这是新客户板并批准完整烧录”后，才可擦除厂家/测试固件并写入基础镜像。写入 Bootloader、分区表、OTA 数据、应用、双 LittleFS 和模型后逐段验证哈希。新板 NVS 应为空，真实秘密由后续手机网页配置。

### 已有客户板

默认不擦除整片。根据变更选择最小写入：

- 仅代码变化：应用分区。
- 本地“我在”录音变化：录音嵌入应用镜像，因此只更新应用分区；含录音镜像必须作为该客户私有产物，不复用给其他客户。
- 唤醒词变化：应用 + model。
- 人格变化：优先经现有 `set_public_config` 更新双 LittleFS；若必须烧录文件系统镜像，明确说明会覆盖人格和公共配置。
- 不覆盖 NVS，除非用户明确批准重新配置或恢复出厂。

写入前列出精确偏移、文件、长度和会保留的分区。禁止对计算所得但未核验的宽泛路径执行擦除或覆盖。

### 不完整板的受控恢复

- Bootloader、分区表或 OTA 数据缺失时，使用本次构建生成的三个精确产物恢复；默认保留 NVS，并逐段读回验证。OTA 数据在首次启动后可能合法改变，以能正常选择应用并启动为验收标准。
- 双 LittleFS 都为空或无法挂载时，先取得“初始化两个 LittleFS 槽”的明确授权。初始化后只恢复本客户已经批准且经过清理的公共人格配置，通过现有 `set_public_config` 写入并确认 generation 递增、A/B 冗余有效。
- 只有一个 LittleFS 槽有效时，不覆盖有效槽；使用现有 A/B 修复逻辑协调另一个槽。
- 模型分区为空或无效时，写入本次构建的 `srmodels.bin` 并读回核对；启动日志必须确认 `wn9_xiaosurou_tts2`。
- NVS 为空不是写入失败，也不能从其他客户恢复。真实 Wi-Fi、API Key 和音色 URI 由本客户之后通过本地网页填写。

## 烧录

- 优先使用当前构建目录生成的 `flash_args`/`flasher_args.json`，不要手写过时的偏移集合。
- esptool 写入后必须得到每段数据哈希验证结果；再独立读取或比较关键分区哈希。
- 不烧写 Flash Encryption、Secure Boot、JTAG 禁用或密钥相关 eFuse。
- 不把真实 Wi-Fi、API Key、音色 URI 或聊天写进可分发的 `.bin`。

## 烧录后最小验证

1. 使用纯串口监视或不会发送设备命令的验证方式；禁止使用会在启动后自动执行 `test_dialog_once` 的旧脚本。
2. Bootloader 能读取分区表并从预期应用分区启动；无 invalid header、崩溃、断言或循环复位。
3. 识别 16 MB Flash 与 8 MB Octal PSRAM。
4. 双 LittleFS 挂载成功；人格公共配置加载成功，只报告 generation、长度和计数，不输出内容。
5. 只加载 `wn9_xiaosurou_tts2`，日志等待“小酥肉”。
6. 长按 BOOT 3 至 10 秒可进入 `GiftDoll-XXXXXX` 配网；本阶段不填真实秘密也可验证热点和页面。
7. 查询配置存在布尔状态。缺少 Wi-Fi、DeepSeek、硅基流动或本轮要求的个人音色配置时停止，让用户通过手机网页补齐。
8. 本地“我在”真机听感只能由用户验收；未经真实云端对话授权，可使用不会进入云链路的诊断固件或仅完成启动验证，不能把叫醒后的完整流程当成免费测试。
9. 未获付费批准时，到唤醒/开始录音或离线诊断为止，不让完整云链路运行。

## 真实配置和一次对话

只有另行批准后才执行：

- 真实 Wi-Fi、DeepSeek Key、硅基流动 Key 和可选音色 URI 由用户在本地网页中填写；不要通过聊天收集或回显。
- 保存后验证设备重启、Wi-Fi 连接和配置存在布尔状态。
- 用户再次批准本次付费测试后，运行恰好一次“小酥肉”完整链路，记录 ASR/LLM/TTS 成功状态、耗时和调用次数，不记录音频、转写正文、回答正文或密钥。
- 只有请求实际开始发往云端时才算消耗本次付费测试授权；若因缺少配置、未连网或本地启动失败而在联网前停止，报告“本次授权未使用”。修复后再次发起真实请求仍需用户确认。
- 音频验收必须由用户确认实际扬声器音量、清晰度和是否仍有播放中卡顿；编译通过和日志成功不能替代听感验收。

## 完成报告

报告目标板标识、写入策略、写入分区、镜像哈希、启动证据、配网证据和是否发生真实 API 调用。明确提示：当前设备未启用 Flash/NVS 加密与 Secure Boot，不能保证捡到设备的人无法提取其固件或配置。
